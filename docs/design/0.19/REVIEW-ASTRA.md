# ClusterVision 0.19 — independent architecture review

**Verdict: ship with 7 changes.** Ship the recorder direction as the plan; reject its present guarantees. Local capture, asynchronous replication and rebuildable views fit twelve hosts. The proposal confuses observations with complete history, transport deduplication with semantic identity, and a reusable read checkpoint with permission to replace live context. Those errors survive a perfectly implemented G-Set.

References below use original file line numbers: **D** = [DESIGN-0.19.md](DESIGN-0.19.md); **I** = [INJECTION-SURFACES.md](INJECTION-SURFACES.md); **DP** = [DATAPATHS.md](DATAPATHS.md); **IF** = [INTERFACE-V2.md](INTERFACE-V2.md); **C** = [CODEC.md](CODEC.md); **CX** = [COMPLEXITY.md](COMPLEXITY.md); **P** = [PERF.md](PERF.md); **F** = [fn-STORAGE-DESIGN.md](fn-STORAGE-DESIGN.md); **E** = [fn-ENVELOPE-AND-HOST.md](fn-ENVELOPE-AND-HOST.md). ## 2. Five entirely absent operational contracts

These are missing protocols, even where §7 names an adjacent risk.

| Missing contract | First-month failure on pug's fleet | Minimum addition |
|---|---|---|
| **Authenticated attribution and payload access** | An agent can POST a row claiming another host or parent; a raw tool result includes credentials and becomes readable to every hub user. A forged parent contaminates the summary source. | Bind append credentials to enrolled producer namespaces; authorize reads by project/principal; use authenticated transport and restrictive local IPC. Separate claimed parent from verified parent. Define redaction before replication and record omissions; raw retention needs explicit access scope. F:39 separates endorsement, authorization and confidentiality. |
| **Request/attempt correlation across the inference cluster** | Two overlapping calls, a retry and an auxiliary summary share D:57's per-session `request_tag`; queue and node data join to the wrong model call. | Stable logical-call ID plus unique attempt/span ID, propagated per request and echoed by the cluster; link retries and subagents explicitly. [W3C Trace Context](https://www.w3.org/TR/trace-context/) supplies request propagation, not a session-wide causal oracle. Where a harness cannot inject per-call IDs, label the join ambiguous. |
| **Evidence custody, deletion and restore** | Host sleeps; transcript cleanup runs before lazy mirroring; a ready summary still cites deleted messages. A shipper cursor survives a hub restore and skips data the restored hub no longer has. | Separate metadata delivery ack, payload-copy receipt and consumer progress; retain required artifacts until the promised custody condition is met. Negotiate restored hub frontiers and replay. Make expiry/unavailable states explicit; deleting payloads does not remove identifiers or backups. F:31–41 and fn-scholar-astra-ch1.md:25 distinguish these contracts. |
| **Shared inference scheduling for precompute** | Fifty sessions cross the threshold together. Background summaries occupy the same saturated inference cluster as foreground turns, raising queue time more than compaction saved. Native and cv precomputers may duplicate work. | One owner/lease per context generation; lower-priority bounded inference admission, per-endpoint concurrency and cancellation, native-precompute detection, recorded token/compute budgets. Show deferred work and fallback; do not quietly truncate context. D:195's “one summary at most” does not follow from repeated idle/threshold triggers. |
| **Fleet rollout and service ownership** | Daily Claude upgrades or a changed feature flag invalidate one plugin. A managed-settings change alters existing hooks; two users start separate appenders; watcher restarts lose work ownership. The recorder looks installed but is inactive. | Versioned effective-config/capability inventory, one local writer owner, explicit user/profile isolation, service restart/upgrade procedure, canary and rollback, and a per-harness support matrix. Unsupported harnesses retain reader-only capability. A code version is insufficient to identify a server-flagged feature. |

## 3. Counter-design: one durable capture boundary, separate execution control

Keep the single cv binary and API. Use three deployment roles: a host capture process, a hub process, and a disposable precompact worker. They can be `cv serve` roles and a `cv watch` consumer; process isolation does not require a second product or duplicated API. A slow transcript normalization must not hold the appender's commit path. IF:23–59's product shape does not decide the failure domains. Also resolve D:326's launcher naming explicitly: overloading `resume` to create a session conflicts with IF:9–11's one-act-per-verb rule and IF:89's existing-session meaning. Prefer an explicit launch mode with documented semantics over a hidden wrapper.

| Area | Alternative and comparison with D |
|---|---|
| **Identity** | An enrolled random `producer_id` identifies a capture namespace; host name/hardware ID are attributes. Each exclusive appender activation creates a fresh random writer epoch, durably before accepting rows; `event_id=(producer_id, epoch, seq)`. This avoids restored counters silently reusing IDs, assuming fresh entropy; divergent identical keys are still quarantined. Restores preserve old epochs and declare discontinuity. A logical conversation gets a cv UUID; native IDs are aliases scoped by harness and store/profile namespace. Each launch/resume gets a distinct run UUID; unlaunched observations acquire one on attachment with `birth_unknown`. This adds aliases but handles migration, profiles and simultaneous resumes that `(host,harness,id)` cannot. Full rollback remains detectable only to independent holders of prior evidence. |
| **Ordering** | Per-writer seq means durable observation order, not execution order. Events carry run, native event/call IDs, causal parent IDs where known, observed wall time and same-process monotonic durations. Keep HLC as optional display/merge metadata if useful, never as a global delivery cursor or completeness claim. A delayed hook stamped at append time does not recover its original happens-before relation. Cross-host causality requires propagation at each relevant send/receive; a birth-time env value alone is insufficient. Partial order plus stable display tie-break is more honest and simpler than promising a causal fleet total order. |
| **Local ledger** | For 0.19, use a **cv-owned SQLite WAL database with one writer and FULL synchronization**, separate from Hermes's database. Store immutable event envelopes/raw payloads, producer operation bindings, durable frontiers and subscription positions transactionally. `append` returns a durable receipt only after commit; lower-latency accepted-but-not-durable receipts must have a distinct type. Callers use stable operation IDs for retries, with request-byte binding. Batched transactions amortize flushes. Compared with custom JSONL, this buys framing, atomic cursor updates and recovery at the cost of SQLite page/index overhead and checkpoint management. It does not inherit Hermes's 50-writer contention: only the cv appender writes this database. Benchmark on the actual filesystem; FULL durability assumes an honest supported storage stack. |
| **Merge and delivery** | Hosts ship committed immutable batches with origin IDs, ranges and checksums. Hub transactionally inserts new IDs and advances each contiguous durable origin frontier; equal ID/equal bytes is a retry, equal ID/different bytes is a conflict. Each first insertion receives a monotonic **hub ingestion offset**. Live `read-after` consumes that offset; event-time displays can reorder and mark late corrections. A reconnect handshake compares frontiers, not a shipper's remembered maximum. Consumers acknowledge only after their own state/effects are durable. On hub rebuild, change the cursor generation and require explicit rebase; original event IDs let consumers dedup. This sacrifices arrival-order-independent cursor numbers, not eventual event-set convergence. |
| **Folds** | Define per-run lifecycle transitions and field provenance: `exit` closes an execution attempt, not every future resume; delayed observations enrich it without reopening it. Unknown/conflicting observations remain visible. Hook, OTel and store observations share a logical operation only with an exact native ID or declared linkage; unmatched ones are not heuristic duplicates. Store repairs append evidence with original event time and later observation time. Deterministic rebuild and incremental late-arrival correction must agree. Raw sets alone provide none of these semantics. |
| **Where the hub lives** | Put one `cv serve` hub on an always-on management machine/VM with persistent local storage and backup, outside GPU job lifecycle, preferably outside inference CPU/disk contention. The exact box is an operational choice absent from the brief; a sleeping workstation is unsuitable. A single hub is sufficient initially: outage pauses global visibility, never local capture or a harness context swap. Rebuild from host logs within their explicit retention contract. Compare D:129's binary choice with this deployment choice: they are independent. No Kafka cluster or fn2 availability dependency is justified for twelve origins. |
| **Large payloads** | Small immutable envelopes reference separately stored large artifacts. Persist artifact and durable manifest before acknowledging the referencing event, or explicitly acknowledge metadata-only capture. Upload in bounded chunks with a final verified receipt; a 1 MiB HTTP guard is not a reason to truncate a tool result. Report bytes captured, redacted, pending and unavailable. This follows F:6's journal/payload split without adopting its storage engine or pretending all rows are small. |
| **Drift** | Freeze raw bytes with native schema/scope, harness version, effective feature/config capability fingerprint and capture-adapter identity. Normalize through one decoder per wire format using the existing demand model, with frozen semantic fixtures across stores/hooks/OTel. Preserve resource/scope envelopes, not just event bodies. Unknown observations remain inspectable; unknown mutation capabilities turn precompact off. Use the existing single stored-format version for derived-state invalidation and measure rebuild work. More version metadata diagnoses drift; it is not permission for competing decoder/cache systems. |

The append/read/wait/ack trait should describe receipt durability, retry identity, cursor generation, gap/rebase, cancellation and ownership of retention. A long-poll must atomically check progress and register its waiter to avoid losing a wake between them. Bound waiters and outstanding bytes with explicit admission/refusal and observable configuration. Matching helm's method names is useful; it does not establish provider substitutability. Fn remains a later provider after it passes exactly these conformance scenarios, including crash/redelivery.

### Precompact handoff

**Default Claude policy: observe its native precompact first.** Pug's reported 47–88 s to 31–134 ms result already belongs to native Claude. Demonstrate an incremental reason to replace its summarizer. The undocumented plugin route gets a capability probe immediately, not a product commitment inferred from a binary string. Hermes's ContextEngine is the first controlled candidate for cv-managed summaries.

1. **Prepare:** the harness adapter captures an immutable context generation and eligible cut, including injected context, system/tool configuration, preserved IDs and complete tool-call/result groups. A worker lease chooses native or cv ownership, records the model/prompt/config and schedules background work. The cv checkpoint accelerates transcript extraction; it does not authorize replacement.
2. **Ready:** publish the candidate artifact atomically with the generation/cut, content commitments and usage. Prefix content can be hashed incrementally when captured. That hash still cannot detect later rewrites by itself: the harness must provide a trusted generation signal or compare the actual context content. Otherwise exact validation incurs a prefix read, or this path is disabled. DP:170–179 rules out a free third option.
3. **Commit:** inside the harness's compaction critical section, compare the candidate's generation/content and all covered/preserved groups against the current context; include D:161's swap-time rejection list, unseen replies, hooks and final token fit. Install once and record the boundary. A completed model summary is not evidence of a completed swap. Reconcile a swap whose receipt was lost from the harness's boundary record on restart.
4. **Miss/failure:** a stale, late, unavailable or unsupported candidate invokes native compaction within a defined deadline. Never wait for the hub. Plugin failure needs a verified native fallback path; a request-rewriting proxy cannot manufacture one, especially after partial response delivery. Session swap remains an explicit new-run operation with lineage, not an invisible recovery tactic.

This costs tighter harness integration and may reject more candidates than D. It prevents fast but incorrect context replacement. Structural validity is still not semantic summary quality: repeated summary-of-summary can lose constraints while retaining every anchor. Keep original evidence available and evaluate multiple consecutive compactions, permissions, pending async results and recovery tasks—not only identifier recall.

## 4. The three decisions I would make differently

| Decision | My choice | Tradeoff that decides it |
|---|---|---|
| **Canonical identity** | Conversation/run/observation identities separated; native ID and host become scoped aliases/attributes. | More metadata and import rules now, fewer irreversible lineage collisions later. Host-qualified native IDs are convenient locators but fail ordinary copy/resume/profile cases. Spend the advertised JSON break on the complete model. |
| **First durable provider** | One cv-owned SQLite writer and transactional receipts/frontiers, not an underspecified JSONL appender. | JSONL is easier to inspect and suffix-copy; SQLite avoids designing atomic append, cursor and dedup recovery simultaneously. Keep logical export and provider boundaries. Neither choice needs fn2's custom engine, and measurements can overturn SQLite if flush/checkpoint interference exceeds the stated budgets. |
| **Precompact ownership** | Instrument native Claude; implement cv replacement first where the adapter controls an atomic handoff, with inference admission. | Less immediate cross-harness uniformity, but avoids reimplementing an already-fast native path and makes context safety testable. Custom summaries earn promotion through quality and total-latency results, not swap latency alone. |

## 5. First build: one host, one week, a falsifiable vertical slice

Build one Hermes recorder, a minimal supervised-launch adapter, the single-writer durable store, and a second local receiver process that speaks the future hub protocol. Add one Claude capability/native-precompact observation spike. No fleet deployment, broad managed-hook rollout, or universal precompact format before these results. The following are proposed experiments; this review executed no agents or fault injection.

| Day | Deliverable | What it resolves |
|---|---|---|
| **1** | Capture a representative Hermes turn with tools, injected context and auxiliary calls; record an independent fixture input/operation manifest. Exercise the Claude plugin route on a disposable session and record the actual capability/flag. | Can the promised facts be observed? Is the replacement interface callable, and who owns native precompute? |
| **2–3** | Local durable append/retry plus receiver/frontier reconciliation. Use a deterministic fault adapter to cut before write, after write/before flush, after flush/before reply, and during recovery; model a restored producer and restored hub. | Every durable receipt survives ordinary crash recovery; uncertain outcomes are retriable without duplication; divergent key reuse is refused; terminal losses are not invented as known gaps. No process killing is needed to model these transitions. |
| **4** | Replay 50 independent Hermes writer workloads against a scratch store, including in-place compaction, large results and one hot session among 49 unchanged sessions. Compare to the current reader using identical snapshots. | Read amplification, native SQLite allocation, certificate invalidation and content correctness—not merely absence of errors after retries. |
| **5** | One ContextEngine prepare/validate/swap path; inject an unsampled middle edit, pending tool reply, injected-context change and competing compaction. Compare native Claude with cv observation enabled. | Does each stale candidate decline before mutation? Does native fallback still work? |
| **6–7** | Interleave baseline/recorder/precompute workloads at recorded inference load; disconnect the local receiver, restore it and drain backlog. Run consecutive compactions with blind task/probe scoring. | Real event/byte rate, backlog capacity, foreground interference, eventual delivery and total task benefit. Twenty compactions are a pilot, not a p99 or noninferiority proof. |

The cheapest decisive test is the 100/110 terminal-tail schedule in §1. Under D7's stated mechanism, it produces zero observed sequence gaps for ten lost rows. The second is a changed covered message with the same anchor. Both challenge guarantees directly; neither requires waiting a week for an incident on the fleet.

## 6. Release-plan conditions

The seven changes below are required amendments to the 0.19 plan. A one-host recorder can ship incrementally; fleet truth and automatic context replacement must wait for their corresponding gates. Preserve raw observations, explicit missing coverage, suffix replication and the optional launcher. Do not claim optional launch supplies universal birth/crash truth: a failed launcher or whole-host power loss leaves an execution outcome unknown until independently reconciled.

REPORT:
Ship with 7 changes.

1. Separate producer, writer epoch, conversation, run and request-attempt identity; define causal versus delivery order.
2. Specify durable receipts, idempotent append, conflict handling, origin frontiers, hub cursors and restore recovery; remove the seq-gap guarantee.
3. Define capture coverage, cross-surface reconciliation and capability/schema drift gates for every supported harness.
4. Repair Hermes snapshot acquisition and content/dependency certificates; preserve complete checkpoint state and verify-on-use.
5. Make precompact an atomic harness-owned handoff with native fallback, one owner and inference budgets; observe native Claude first.
6. Specify hub placement/operations, authentication, payload access, evidence custody, retention and explicit capacity behavior.
7. Replace the layer-first rollout with the one-week vertical slice and independent durability, completeness, safety and interference gates.
